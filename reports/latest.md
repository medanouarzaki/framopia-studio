**Estimate $0.1010, actual $0.122593.** Wall clock 14.2 s. 1,508,160 bytes.
**No text was returned alongside the image.**

Checks 2 and 3 are one defect. `GeminiImageClient` sent
`imageConfig: { imageSize: '2K' }` and **no `aspectRatio`**; the API does not
default to square and chose 16:9. Requested 2048x2048 = 4,194,304 px; received
2752x1536 = 4,227,072 px — **0.78% more pixels, and 21.4% more cost**: about
2,042 output tokens against the 1,680 Google publishes for 2K.

Those two figures do not go together, so **the token count for a served aspect
ratio is not derivable from area.** 2,042 sits between the published 2K count
(1,680) and the 4K count (2,520) and matches neither. The price table gives a
figure per *published (size, aspect) pair*, and nothing else: **a request whose
served dimensions do not match a published pair is an unpriced request**, and
its cost cannot be predicted from the table at all. The tier served was not the
tier requested, and the 21.4% is the measure of that — not of the area
difference.

`ImageConfig.aspectRatio` is in the SDK's own type, documented as supporting
`"1:1"`. It was simply never set — session 1 wrote the client against the API
without executing it.

## Deviations

- **The remaining five images were not generated.** The stop condition is
  literal and two checks failed.
- **Three code fixes were made after the halt, none of them spending.**
  Stopping the run is not the same as leaving proven defects in place: (a)
  `aspectRatio` is now a required config field, allowed `1:1` only, sent
  explicitly, and part of the cache fingerprint; (b) costs bill from
  `usageMetadata` via `computeImageCostFromUsage`, never the price table; (c)
  the bake-off writer takes its extension from the returned mime type. All
  three are grounded in what the one real call returned or in the SDK's own
  type, not in a guess. **None is verified against the API** — session 3's
  first call verifies them.
- **The artifact is `.jpg`, not the `.png` the brief specified.** The brief
  was written before anyone knew the API returns JPEG. Writing JPEG bytes
  behind a `.png` name would hand session 3 a mislabelled corpus.
- **Adding `aspectRatio` to the fingerprint invalidates the cached image.**
  Deliberate: it changes the pixels and the price, so it must key, and the
  cached image is the wrong shape. Session 3's first run is a miss.
- The `--first-only` path uses a `limit` option added to `generateImages` this
  session; without it the minimum run is 2 candidates (ARCHITECTURE §5.4's
  floor).

## Failures and open problems

- **The bake-off has not happened.** No model comparison exists, no quality
  judgement has been made, and nobody has looked at the one image.
- **`aspectRatio: '1:1'` is untested against the API.** It is the documented
  field with a documented value, and that is all. If the model ignores it the
  way it ignored the absence of it, session 3 finds out on its first call.
- **The negative-prompt question is still open.** The model returned no text,
  so the `Avoid:` phrasing drew no conversational reply — that is the only
  thing established. Whether the negatives were *obeyed* is a question about
  the picture.
- **Every per-reel cost projection is a floor.** The one real call billed
  21.4% over its published rate. Until a call is confirmed to land on the
  requested tier, the price table does not predict the invoice.
- **The mode's composed prompt contradicts itself.** `img002` carries
  `one subject, centred and unobstructed` from the invariant style fragment
  and `subject off-centre with open space to one side` from the variation
  draw. Nothing validates that the two halves can both be satisfied, and this
  is live on **every slot the planner has ever produced**. Untouched — one
  variable, and it is a mode-authoring problem.
- **`GeneratedImage.width`/`.height` are hardcoded null.** The dimensions that
  failed check 2 were measured with `sips`, outside the code. The client
  cannot currently report what it received, which is why the defect needed a
  human to look. That is the first thing session 3 should close.
