# Block 7 — how big the images could actually be

Generated by `npm run image-size`. **No constant was changed.** The user ruled the
images too small, which settles the question Block 5 left open; this measures the
ceiling so the choice is made against numbers and a built comp.

Three rules, successively looser:

- **(a) as built today** — inside the assigned zone, `FILL_FRACTION` 0.88, with
  jitter (±0.08) and edge clearance.
- **(b) fill the zone** — same zone, same clearance, `FILL_FRACTION` 1.0.
- **(c) maximum allowed** — anywhere in the frame, clear of the head mask plus
  `HEAD_CLEARANCE` 0.04, outside the subtitle band and the bottom exclusion,
  inside the frame. **The zone rectangle is not a constraint here** — it was a
  conservative device for finding free space, never itself a product rule.

**(b) cannot keep the jitter.** At `FILL_FRACTION` 1.0 the square already fills the
region, so a jitter upward would leave it — the solver draws the side before the
position precisely so that cannot happen. (b) is therefore the zone-filling ceiling,
with no jitter, and that is a property of the two settings together rather than an
omission.

## Caveats

- **(c) uses the head mask's bounding box**, unioned over the frames the slot is on
  screen, not its silhouette. A box is conservative where the head is not square, so
  (c) is a floor on the true ceiling rather than the exact one.
- **(c) ignores concurrent elements.** ARCHITECTURE §5.3 plans non-overlapping image
  windows and no fixture has two slots overlapping in time, so nothing was excluded —
  but the rule is unexercised and a reel that did overlap would need it.
- `CARD_EDGE_CLEARANCE` 0.02 still applies to (a) and (b) and is not applied in (c),
  because it insets from a zone edge and (c) has no zone.
